# Лабораторная работа №12
## Инициализация сетевого сокета на уровне машинных инструкций процессора (NASM)

**Цель работы:** изучить создание TCP-сокета, подключение и отправку данных через прямые системные вызовы Linux x86-64.

**Среда:** Linux/WSL x86-64, NASM, ld, netcat, strace.

## Сборка и запуск

В первом терминале запускается слушатель:

```bash
nc -l -p 8080
```

Во втором терминале выполняются сборка и запуск клиента:

```bash
nasm -f elf64 asm_client.asm -o asm_client.o
ld asm_client.o -o asm_client
./asm_client
```

## Результат передачи данных

В терминале netcat появилась строка:

```text
Hello from clean NASM assembly code!
```

После передачи соединение закрылось, netcat завершил работу.

## Исследовательский эксперимент

При выключенном netcat клиент был запущен через:

```bash
strace ./asm_client
```

Получены следующие результаты:

```text
socket(AF_INET, SOCK_STREAM, IPPROTO_IP) = 3
connect(3, {sa_family=AF_INET, sin_port=htons(8080), sin_addr=inet_addr("127.0.0.1")}, 16) = -1 ECONNREFUSED (Connection refused)
write(3, "Hello from clean NASM assembly c"..., 37) = -1 EPIPE (Broken pipe)
--- SIGPIPE ---
+++ killed by SIGPIPE +++
```

Сокет создан с дескриптором 3. Подключение отклонено, поскольку на порту 8080 отсутствовал слушатель.

В исходном коде результат connect не проверяется. Поэтому программа попыталась записать данные в неподключённый сокет. Возникли EPIPE и сигнал SIGPIPE, завершивший процесс до выполнения sys_exit.

## Ответы на контрольные вопросы

### 1. Зачем изменялся порядок байт порта и IP-адреса?

В x86-64 многобайтовые числа хранятся в порядке Little-Endian: младший байт располагается по меньшему адресу памяти. Сетевые поля порта и IPv4-адреса используют Big-Endian: старший байт идёт первым.

Порт 8080 равен 0x1F90. Объявление `dw 0x901F` на x86-64 создаёт в памяти байты `1F 90`, необходимые для сетевого представления порта.

Объявление `dd 0x0100007F` создаёт байты `7F 00 00 01`, соответствующие адресу 127.0.0.1.

Поле семейства адресов AF_INET хранится в порядке байт компьютера, поэтому для него используется `dw 2`, создающее байты `02 00`.

### 2. В каком регистре находится код ошибки connect?

При прямом системном вызове Linux x86-64 результат возвращается в регистре RAX.

При ошибке RAX содержит отрицательный номер ошибки. Для ECONNREFUSED в Linux x86-64 это -111. Такое значение можно увидеть в отладчике сразу после инструкции syscall, выполняющей connect, до следующего изменения RAX.

Ядро возвращает отрицательное значение в пользовательский код. strace расшифровывает его и показывает привычную запись `-1 ECONNREFUSED`.

### 3. Во что превращается socket.send() из Python?

Python получает объект с данными в байтах и через свою реализацию модуля socket обращается к сетевому интерфейсу операционной системы.

В Linux отправка может выполняться системным вызовом sendto с неуказанным адресом для уже подключённого TCP-сокета. На уровне Linux x86-64 номер системного вызова помещается в RAX, а аргументы — в RDI, RSI, RDX и при необходимости R10, R8, R9. Инструкция syscall передаёт управление ядру.

Ядро получает дескриптор сокета, адрес буфера и количество байтов, обрабатывает данные сетевым стеком и возвращает результат через RAX.

В NASM-программе этой работы отправка выполняется через write: RAX = 1, RDI содержит дескриптор сокета, RSI — адрес строки, RDX — её длину. Сетевой сокет допускает запись через этот системный вызов.
